# Паспорт проекта

## Название

Barbershop Booking — сервис онлайн-записи в барбершоп.

## Происхождение

Новый проект, создаваемый с нуля для лабораторных работ по программной инженерии.

## Назначение и решаемая проблема

Сервис должен упростить запись клиентов в барбершоп и сократить ручную работу администратора. Клиент выбирает услугу, барбера и свободное время. Барбер видит своё расписание, а администратор управляет услугами, сотрудниками и записями.

## Целевые пользователи и роли

| Роль | Назначение |
|---|---|
| Клиент | Просматривает услуги и барберов, создаёт, переносит и отменяет запись. |
| Барбер | Просматривает своё расписание и изменяет статус визита. |
| Администратор | Управляет услугами, расписанием барберов и всеми записями. |

## Основные функции

1. Регистрация и вход пользователя.
2. Просмотр списка услуг и цен.
3. Просмотр списка барберов.
4. Просмотр свободных временных слотов.
5. Создание записи на услугу.
6. Отмена или перенос записи клиентом.
7. Просмотр расписания барбером.
8. Управление услугами и записями администратором.

## Предметные сущности

Пользователь, барбер, услуга, запись, временной слот.

## Технологический стек

Java 21, Spring Boot 3.3.5, Spring Web, Spring Data JPA, Bean Validation, PostgreSQL 16.4, Maven, Docker Compose.

## Структура проекта

На текущем этапе подготовлены:

- `src/main/java` — исходный код Spring Boot приложения;
- `src/main/resources` — конфигурация приложения;
- `src/test` — автоматические тесты;
- `docs` — документация проекта;
- `tests` — место для дополнительных сценариев и материалов тестирования;
- `docker-compose.yml` — запуск приложения вместе с PostgreSQL;
- `Dockerfile` — сборка контейнера приложения.

Точка входа — класс `BarbershopApplication`. Проверочный HTTP endpoint — `GET /api/health`.

Внешняя зависимость проекта — PostgreSQL. Параметры подключения задаются переменными окружения `SPRING_DATASOURCE_URL`, `SPRING_DATASOURCE_USERNAME` и `SPRING_DATASOURCE_PASSWORD`.

## Первые наблюдения и вопросы

1. Нужно определить правила пересечения записей и блокировки занятого времени.
2. Нужно уточнить, может ли клиент самостоятельно переносить запись и за какой срок до визита.
3. Нужно определить права администратора и способ первоначального создания учётной записи администратора.

Эти наблюдения будут оформлены отдельными issues после создания репозитория.

## Выполнимость и план

### Риски

| Риск | Вероятность | Последствия | Снижение риска |
|---|---|---|---|
| Незнакомые возможности Spring Security | Средняя | Задержка авторизации | Начать с минимальной модели ролей и отдельного прототипа входа. |
| Ошибки в правилах расписания | Средняя | Некорректные записи | Зафиксировать сценарии конфликтов и покрыть их тестами. |
| Различия окружения | Средняя | Проект не запускается у проверяющего | Использовать Docker Compose и фиксированные версии образов. |
| Ограниченное время | Средняя | Часть функций не войдёт в семестр | Сначала реализовать запись, расписание и роли; дополнительные функции оставить за пределами MVP. |

### План лабораторных работ

| Работа | План | Оценка |
|---|---|---:|
| Лабораторная 2 | Сформировать пользовательские, функциональные и нефункциональные требования для MVP. | 6 ч |
| Лабораторная 3 | Спроектировать архитектуру, модель данных и API. | 8 ч |
| Лабораторная 4 | Реализовать пользователей, услуги, расписание и создание записи. | 16 ч |
| Лабораторная 5 | Подготовить тесты, проверить граничные случаи и исправить дефекты. | 12 ч |
| Лабораторная 6 | Подготовить сборку, развёртывание и итоговую документацию. | 8 ч |

### Предварительный объём семестра

В MVP входят регистрация и роли, каталог услуг, список барберов, расписание, создание, перенос и отмена записи. За пределами MVP пока остаются онлайн-оплата, уведомления по SMS или электронной почте, программа лояльности и несколько филиалов.
